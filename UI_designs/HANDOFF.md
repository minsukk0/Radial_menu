# 휠클릭 래디얼 메뉴 · 구현 핸드오프

기준 시안: 시안 B "다크 계기판"과 "항목 추가 화면" (2026-10-05 확정본)

이 문서 하나로 구현을 시작할 수 있게 썼다. 사람이 읽어도 되고 코딩 도구에 그대로 넘겨도 된다.

## 1. 무엇을 만드는가

마우스 휠 버튼을 누르면 커서 위치에 원형 메뉴가 뜨는 윈도우 유틸리티다. 메뉴는 2단이다.

- **상위 칸은 분류**다. 앱, 터미널, 폴더·주소, 시스템 네 종류가 있고, 사용자는 쓰는 분류만 추가한다.
- **하위 칸은 그 분류에 등록한 항목**이다. 분류를 가리키면 그쪽 바깥에만 띠 모양으로 펼쳐진다.
- 한 분류에는 한 종류의 항목만 담는다. 앱 분류에 스크립트를 넣는 식의 섞기는 없다.

## 3. 자료 구조

설정 파일 하나에 분류와 항목을 순서대로 담는다. 배열 순서가 화면 순서다(12시 방향부터 시계 방향). 아래 필드는 항목 추가 창의 입력란과 일대일로 대응한다.

```json
{
  "version": 1,
  "accent": "#1E9BFF",
  "categories": [
    { "kind": "app", "label": "앱", "items": [
      { "label": "메모장", "path": "C:\\Windows\\System32\\notepad.exe", "args": "",
        "whenRunning": "focus", "runAsAdmin": false }
    ] },
    { "kind": "terminal", "label": "터미널", "items": [
      { "label": "새 창", "icon": "window", "action": "open",
        "shell": "powershell", "startDir": "{현재 폴더}", "runAsAdmin": false, "reuseTab": true },
      { "label": "변환 스크립트", "icon": "terminal", "action": "run", "mode": "command",
        "command": "python convert.py \"{선택한 파일}\" --out \"{현재 폴더}\"",
        "shell": "powershell", "workDir": "{현재 폴더}", "window": "hidden",
        "runAsAdmin": false, "notifyOnDone": true, "copyOutput": false, "confirmFirst": false }
    ] },
    { "kind": "folder", "label": "폴더·주소", "items": [
      { "label": "사진", "icon": "folder", "target": "C:\\Users\\me\\Pictures", "openWith": "default" }
    ] },
    { "kind": "system", "label": "시스템", "items": [
      { "label": "잠금", "fn": "lock" }
    ] }
  ]
}
```

값의 범위:

- `whenRunning`: `focus`(창 앞으로 가져오기) 또는 `new`(새로 실행)
- 터미널 `action`: `run`(명령·스크립트 실행) 또는 `open`(새 창 열기)
- 터미널 `mode`: `command`(한 줄 명령) 또는 `file`(파일 지정. 이때 `file`과 `args`를 쓴다)
- `shell`: `powershell`, `cmd`, `wsl`, `gitbash`
- `window`: `hidden`(숨김), `visible`(터미널 표시), `keep`(끝난 뒤 창 유지)
- `openWith`: `default`, `explorer`, `browser`
- 시스템 `fn`: 시안에 나온 것은 `lock`, `sleep`, `settings`, `taskmgr`, `mute`, `brightness`, `screenoff`, `emptybin`
- 명령과 경로 안의 자리표시: `{클립보드}`, `{선택한 파일}`, `{현재 폴더}`, `{활성 창 제목}`. 메뉴를 연 순간의 값으로 바꿔 넣는다.

앱 항목의 아이콘은 프로그램에서 자동으로 가져온다. 시안의 "Co", "Cl" 같은 두 글자 네모는 그 자리를 표시한 임시 그림이다. 시스템 항목의 아이콘은 기능에 따라 정해진다. 터미널과 폴더·주소 항목만 사용자가 아이콘을 고른다.

## 4. 메뉴 화면

### 4.1 구성 요소

안쪽부터 순서대로다. 반지름은 메뉴 중심 기준, 100% 배율 px이다.

| 요소 | 치수 | 설명 |
|---|---|---|
| 닫기 버튼 | 반지름 30 | 아쿠아 1px 테두리. 누르면 선택이 풀리고 하위 띠가 사라진다 |
| 중심 쪽 원호 | 반지름 36, 굵기 4 | 선택된 칸의 각도만큼. 시안색, 끝이 둥글고 빛 번짐이 있다 |
| 상위 칸 | 반지름 38 ~ 186 | 각진 부채꼴. 아이콘 24px과 이름이 반지름 116 위치에 놓인다 |
| 원판 외곽선 | 반지름 186 | 아쿠아, 굵기 0.6, 불투명도 0.55 |
| 선택 하이라이트 | 반지름 38 ~ 218 | 강조색 방사형 그라데이션. 원판 밖 218까지 번지며 사라진다 |
| 하위 띠 | 반지름 196 ~ 278 | 모서리 14로 둥근 부채꼴. 원판과 10px 떨어져 있다 |
| 하위 칸 | 반지름 200 ~ 274 | 모서리 10으로 둥근 부채꼴. 칸 사이 4px. 아이콘 20px과 이름이 반지름 237 위치 |

메뉴 전체 지름은 556이다. 그림자 여유를 더해 창은 680×680을 권장한다.

### 4.2 칸 배치 규칙

계산은 `reference/radial-layout.js`의 `layout(categories, hot)`에 모두 들어 있다.

**상위 링**

1. 칸 수 = max(4, 분류 수). 원을 그 수로 똑같이 나눈다.
2. 첫 분류의 중심이 12시 방향이고 시계 방향으로 채운다.
3. 분류가 4개보다 적으면 남는 칸은 빈칸이다. 빈칸 중 첫 칸에만 "분류 추가"를 표시한다.

**하위 링**

1. 칸 수 = max(4, 항목 수 + 1). 더해지는 한 칸은 "추가" 칸이다.
2. 칸 각도는 24도다. 칸 각도의 합이 216도를 넘으면 칸 각도 = 216 ÷ 칸 수로 줄인다. 즉 9칸까지는 띠가 옆으로 넓어지고, 10칸부터 칸이 좁아진다.
3. 띠는 선택된 상위 칸의 중심 방향에 가운데를 맞춘다. 띠 전체 각도 = 칸 각도 합 + 4도.
4. 항목은 시계 방향으로 놓는다. 단 상위 칸의 중심이 180도 이상(아래쪽과 왼쪽)이면 순서를 뒤집는다. 아래쪽에서는 왼쪽에서 오른쪽으로, 왼쪽에서는 위에서 아래로 읽히게 하기 위해서다.
5. "추가" 칸은 항상 마지막 항목 다음에 온다. 그 뒤로 남는 칸은 비워 둔다.

### 4.3 상태

| 대상 | 상태 | 모습 |
|---|---|---|
| 상위 칸 | 평상시 | 글자와 아이콘 `#C6D8DA` |
| 상위 칸 | 선택됨 | 글자 흰색, 아이콘+이름 1.07배, 강조색 하이라이트와 시안 원호가 이 칸으로 온다 |
| 상위 빈칸 | 첫 칸 | 점선 원 안의 +, "분류 추가". 가리키면 아쿠아색 글자와 옅은 아쿠아 바탕 |
| 상위 빈칸 | 나머지 | 아무것도 없고 반응하지 않는다 |
| 하위 칸 | 평상시 | 글자와 아이콘 `#C6D8DA` |
| 하위 칸 | 가리킴 | 글자 흰색, 강조색 방사형 바탕이 0.14초에 걸쳐 켜진다 |
| 하위 "추가" 칸 | 평상시/가리킴 | 흐린 글자 → 아쿠아색 글자와 옅은 아쿠아 바탕 |
| 메뉴 전체 | 선택 없음 | 하이라이트와 하위 띠가 없다 (`08-menu-nothing-selected.png`) |

캡처 `01-menu-apps.png`과 `07-menu-two-categories.png`에서 "claude" 칸이 파랗게 보이는 것은 가리킨 상태를 보여주려고 넣은 시연용 표시다. 실제로는 커서가 올라간 칸만 켜진다.

## 5. 항목 추가 창

하위 링의 "추가" 칸을 누르면 뜬다. 어느 분류에서 눌렀는지에 따라 제목과 입력란이 정해지며, 창 안에서 분류를 바꾸는 수단은 없다.

**공통 구조** (840×640)

- 위: 제목("앱 추가", "터미널 항목 추가", "폴더·주소 추가", "시스템 기능 추가")과 닫기
- 왼쪽 단(248px): 들어갈 자리 미리보기, 이름 입력, 아이콘
- 오른쪽 단: 분류 안내 상자와 분류별 입력란
- 아래: 들어갈 자리 안내 문구, 취소, 추가

**분류별 입력란**

| 분류 | 입력란 | 캡처 |
|---|---|---|
| 앱 | 프로그램 경로 + 찾아보기, "실행 중인 앱에서 고르기", 실행 인수, 실행 중이면(창 앞으로 가져오기 / 새로 실행), 관리자 권한 | `11` |
| 터미널 · 명령·스크립트 실행 | 방식(한 줄 명령 / 파일 지정), 명령 또는 파일+넘길 값, 셸, 작업 폴더, 창 표시, 옵션 4개(관리자 권한, 끝나면 알림, 출력을 클립보드에 복사, 실행 전에 한 번 확인). 아래 줄에 "테스트 실행" | `12`, `13` |
| 터미널 · 새 창 열기 | 셸, 시작 폴더, 관리자 권한, 열린 터미널이 있으면 새 탭으로 | `14` |
| 폴더·주소 | 경로 또는 주소 + 찾아보기, 여는 방법(기본 앱 / 탐색기 / 브라우저) | `15` |
| 시스템 | 기능 타일에서 하나 고르기. 이미 등록한 기능은 점선 테두리에 "등록됨"으로 표시하고 고를 수 없다. 고르면 이름이 기능 이름으로 채워진다 | `16` |

**시안에서 모양만 있는 부분**

- 경로, 명령, 실행 인수 칸은 예시 글자가 든 그림이다. 실제로는 입력란이어야 한다. 시안에서 입력되는 칸은 이름뿐이다.
- "넣을 값" 칩은 누르면 명령의 커서 위치에 그 자리표시가 들어가야 한다.
- 찾아보기, 실행 중인 앱에서 고르기, 테스트 실행은 동작이 없다.

## 6. 디자인 토큰

원본은 `tokens/tokens.json`이고 모든 값에 쓰임새 설명이 붙어 있다. `tokens.css`는 같은 값을 `--rm-` 접두어 변수로 옮긴 것이다.

**묶음**

| 묶음 | 내용 |
|---|---|
| `color.accent` | 강조색. 기본 `#1E9BFF`, 선택지 `#3D7BFF`, `#6E56CF`, `#D6409F` |
| `color.on-accent` | 강조색 채움 위의 글자색 두 가지 |
| `color.highlight` | 시안 `#2CE8FF`와 그 빛 번짐 |
| `color.line` | 아쿠아 `#A6F1EC` 한 가지 |
| `color.surface` | 원판, 띠, 닫기 버튼, 창, 입력란 등 바탕 15가지 |
| `color.text` | 글자 10가지 |
| `opacity` | 아쿠아 선에 곱하는 불투명도 8가지 |
| `gradient` | 선택 하이라이트, 선택 테두리, 칸 구분선, 하위 칸 하이라이트의 [반지름, 불투명도] 목록 |
| `shadow` | 원판, 창, 글자, 아이콘, 원호 빛 번짐 |
| `font` | 글꼴 묶음 두 가지와 글자 스타일 13가지 |
| `menu` | 메뉴 반지름, 각도, 크기 |
| `dialog` | 항목 추가 창 치수 |
| `motion` | 가감속 두 가지와 시간 |

**쓰는 규칙**

1. **사용자가 바꾸는 색은 강조색 하나다.** 선택 하이라이트, 하위 칸 하이라이트, 켜진 토글, "추가" 버튼이 모두 이 값에서 나온다. 다른 색은 고정이다.
2. **가는 선은 전부 아쿠아 한 색에 불투명도만 달리한다.** 새 선이 필요하면 색을 추가하지 말고 `opacity` 묶음에 값을 더한다.
3. **강조색 위의 글자색은 계산으로 고른다.** 강조색의 상대 휘도가 0.2 이상이면 `#04121C`, 미만이면 흰색이다. 네 선택지 중 보라(`#6E56CF`)만 흰 글자가 되고 나머지 셋은 어두운 글자가 된다. 이렇게 고르면 네 경우 모두 명도 대비가 4.5:1을 넘는다.
4. **그라데이션은 모두 메뉴 중심을 원점으로 하는 방사형이다.** 칸마다 따로 원점을 잡지 않는다. `tokens.css`의 그라데이션 변수는 `--rm-cx`, `--rm-cy`로 중심을 받는다.
5. **메뉴 바탕은 거의 검은색 70%다.** 어두우면서도 뒤가 비치는 느낌이 이 값에서 나오므로 색을 밝히거나 불투명도를 올리지 않는다.
6. **길이는 100% 배율 기준이다.** 화면 배율이 150%면 모든 치수와 창 크기에 1.5를 곱한다.

글꼴은 IBM Plex Sans KR(400, 500, 600)과 IBM Plex Mono(400, 500)다. SIL 오픈 폰트 라이선스라 앱에 함께 넣어 배포할 수 있다. 네트워크에서 받아 오지 말고 파일로 묶는다.

아이콘은 24 격자에 선 굵기 1.5, 끝과 모서리가 둥근 선 아이콘이다. `menu-standalone.html`과 시안 원본 안에 SVG로 들어 있다.

## 7. 시안과 실제 구현이 달라지는 곳

1. **뒤 화면 흐림 1px.** 시안은 메뉴 뒤를 1px 흐리게 했다. 투명 창에서 CSS의 `backdrop-filter`는 페이지 안의 내용만 흐리게 하고 창 뒤의 바탕 화면에는 닿지 않는다. 1px은 눈에 거의 띄지 않는 값이므로 빼는 것을 권한다.
2. **배경.** 시안의 회색 바탕과 창 두 개는 반투명이 보이게 하려고 그린 가짜 바탕 화면이다. 구현에는 넣지 않는다.
3. **앱 아이콘.** 두 글자 네모 대신 프로그램 파일에서 뽑은 아이콘을 20px로 넣는다. 색이 있는 아이콘이 어두운 바탕에서 어떻게 보이는지는 실제로 넣어 보고 정해야 한다.
4. **선택 방식.** 시안은 상위 칸에 커서가 올라가면 선택된다. 칸 모양이 아닌 각도로 판정하려면 `radial-layout.js`의 `hitTest(x, y, 칸 수)`를 쓴다.

## 8. 아직 정하지 않은 것

**디자인 과정에서 임의로 정했고 확인이 필요한 것**

- 하위 링에 "추가" 칸을 항상 하나 붙인다. 그래서 칸 수는 등록 수보다 하나 많다.
- 하위 띠는 9칸까지 넓어지고 그 뒤로 칸이 좁아진다.
- 한 분류의 항목 수 상한은 정하지 않았다. 시안은 앱 10개까지만 그려 봤다.
- "실행 전에 한 번 확인" 옵션은 요청에 없던 것을 넣었다.

**그리지 않은 화면**

- 상위 빈칸의 "분류 추가"를 눌렀을 때의 화면
- 등록한 항목을 고치거나 지우거나 순서를 바꾸는 화면
- 전체 설정 화면(강조색, 시작 시 실행 등)과 트레이 메뉴
- 스크립트가 끝났을 때의 알림

**정하지 않은 동작**

- 메뉴를 어떻게 닫는가. 시안에는 가운데 닫기 버튼만 있다. 메뉴 밖을 누르거나 Esc를 눌렀을 때의 동작은 정하지 않았다.
- 휠 버튼을 짧게 눌렀을 때 원래의 휠클릭(새 탭 열기 등)을 살릴지, 살린다면 몇 ms로 구분할지
- 누른 채로 방향으로 밀고 떼면 실행하는 방식을 넣을지
- 커서가 화면 가장자리에 있을 때 메뉴를 어디에 띄울지
- 게임이나 전체 화면 프로그램에서 끌지

## 9. 권장 스택

### 9.1 이 앱이 스택에 요구하는 것

1. **전역 마우스 훅.** 어떤 프로그램이 앞에 있든 휠 버튼을 가로채야 한다. 윈도우의 저수준 마우스 훅(`WH_MOUSE_LL`)을 쓴다. 훅을 건 스레드에 메시지 루프가 있어야 하고, 훅 함수가 제한 시간을 넘기면 윈도우 7 이후로는 훅이 통보 없이 제거된다. 제한 시간은 윈도우 10 1709부터 최대 1초다. 그래서 훅은 전용 스레드에서 돌리고 일은 다른 스레드로 넘긴 뒤 바로 반환해야 한다. 0이 아닌 값을 반환하면 그 입력이 다른 프로그램에 전달되지 않는다.
2. **투명하고, 테두리가 없고, 항상 위에 있고, 포커스를 뺏지 않는 창.** 포커스를 뺏으면 "지금 쓰는 창"이 메뉴로 바뀌어 `{활성 창 제목}`이나 붙여넣기가 엉뚱한 곳으로 간다.
3. **빠른 등장.** 창을 미리 만들어 숨겨 두고, 누를 때는 위치만 옮겨 보여준다.
4. **윈도우 기능 호출.** 프로그램 실행, 셸 실행, 관리자 권한 요청, 탐색기의 현재 폴더와 선택 파일 읽기, 프로그램 아이콘 뽑기, 트레이, 시작 시 실행.

### 9.2 권장: Tauri 2 (Rust + WebView2) + TypeScript

- **시안을 거의 그대로 쓴다.** 메뉴는 이미 HTML, CSS, SVG로 그려져 있고 `menu-standalone.html`, `radial-layout.js`, `tokens.css`를 화면 쪽 출발점으로 옮기면 된다. 모양과 모션을 다시 만드는 일이 없다.
- **창 설정이 요구와 맞는다.** 창 설정에 `transparent`, `alwaysOnTop`, `skipTaskbar`, `focusable`, `decorations`, `shadow`, `visible`이 있다(tauri-utils 2.10.1 문서 기준).
- **윈도우 기능은 Rust에서 직접 부른다.** 훅과 창 스타일은 `windows` 크레이트로 Win32를 호출해 처리한다.
- **화면 쪽은 가볍게.** 메뉴는 프레임워크 없이 TypeScript로 충분하다. 항목 추가 창과 설정 창은 입력란이 많으니 Svelte나 React 같은 것을 써도 된다.

알아 둘 점:

- 윈도우에서 투명 창이 안 먹는 사례는 그림자 기본값 때문이었다. `decorations: false`, `transparent: true`, `shadow: false`를 함께 준다.
- WebView2의 기본 배경색은 완전 투명(알파 0)과 완전 불투명(255)만 받는다. 바탕을 완전 투명으로 두고 반투명은 페이지의 CSS로 그리는 방식이어야 한다.

### 9.3 대안

| 스택 | 맞는 경우 | 걸리는 점 |
|---|---|---|
| **C# + WPF** | 한 언어로 끝내고 싶고 XAML에 익숙할 때. 훅과 창 스타일은 P/Invoke로 처리하고, 투명 창은 `AllowsTransparency`로 된다 | 메뉴 모양, 그라데이션, 모션을 XAML로 다시 만들어야 한다. `radial-layout.js`의 식은 그대로 옮길 수 있다 |
| **Electron** | 네이티브 쪽까지 자바스크립트 생태계로 가고 싶을 때. 화면 재사용은 Tauri와 같다 | 실행 파일과 메모리가 크다. 전역 마우스 훅은 네이티브 모듈이 필요하다 |
| **AutoHotkey v2** | 짧게/길게 구분, 누른 채 밀고 떼기 같은 입력 동작만 먼저 손으로 느껴 보고 싶을 때 | 이 시안 수준의 화면을 그리기는 어렵다. 본 구현용이 아니다 |

WinUI 3은 권하지 않는다. 테두리 없는 투명 창을 지원해 달라는 요청이 오래 열려 있고, 관련 이슈는 같은 주제의 다른 이슈로 합쳐진 상태다.

### 9.4 먼저 확인할 것

화면을 옮기기 전에 아래 네 가지를 작은 실험으로 확인한다. 이 문서의 스택 판단은 공식 문서를 근거로 한 것이고 실제 윈도우에서 돌려 본 결과가 아니다.

1. 투명 창 위의 반투명 원판이 바탕 화면과 제대로 섞여 보이는가.
2. 창이 포커스를 뺏지 않으면서 호버와 클릭을 받는가.
3. 휠 버튼을 누른 순간부터 메뉴가 보일 때까지 걸리는 시간이 체감상 즉시인가.
4. 관리자 권한으로 실행 중인 프로그램이 앞에 있을 때 훅이 동작하는가. 일반 권한 프로세스의 훅은 이 경우 입력을 받지 못하는 것으로 알려져 있다.

### 9.5 구현 순서 제안

1. 9.4의 실험 네 가지
2. 메뉴 화면: `menu-standalone.html`을 옮기고 설정 파일에서 분류와 항목을 읽어 그리기
3. 실행기: 앱 실행, 폴더·주소 열기, 시스템 기능
4. 터미널: 새 창 열기, 명령·스크립트 실행, 자리표시 채우기
5. 항목 추가 창과 설정 저장
6. 8장의 미정 항목을 정한 뒤 나머지 화면

## 10. 이 묶음을 어떻게 확인했는가

- `radial-layout.js`가 내는 모양을 캔버스 시안과 비교했다. 분류 수와 앱 수를 바꾼 5가지 구성에서 가리키는 분류를 하나씩 바꿔 가며 칸 모양, 구분선, 하이라이트, 띠, 하위 칸 모양과 이름 위치, 등장 지연을 136번 비교했고 모두 같았다(등장 지연은 반올림 차이 1ms 이내).
- `menu-standalone.html`을 시안과 같은 상태로 캡처해 픽셀 단위로 비교했고 차이가 없었다. 이 비교는 시안의 흐림을 0으로 두고 했다.
- 캡처는 글꼴 서버에 닿지 않는 환경에서 찍어서 대체 글꼴로 그려졌다. 실제 글꼴인 IBM Plex Sans KR에서는 글자 폭이 조금 다르다.
- 윈도우에서 실제로 실행해 본 것은 없다.
